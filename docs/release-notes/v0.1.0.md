AI Gateway v0.1.0

A zero-trust gateway between AI clients and the MCP tools they call, for the fictional Harborline
Supply Co. (all data synthetic). Feature complete for the portfolio project: Phases 1 to 4.

What it does
- Authenticates every request (bearer tokens, stored as hashes) and authorises each tool per client.
- Runs every call through a layer chain: scope, allowlist (value rules per client), rate limits, schema
  (arguments against the reviewed input schema), pinned descriptions (a tool whose description or input
  or output schema drifted from the reviewed pin is hidden and refused), egress (data read in a session
  does not flow back out through a write), canary (decoy values), the injection classifier (a small model
  judging free text, answered from committed recordings by default, so the stack runs with no API key),
  and approval (a person approves every write; agent-core v0.1.0).
- Records every decision in a tamper-evident audit chain (anchored and verifiable), and in telemetry
  that a read-only dashboard shows: calls, the layer that stopped each, approvals, and the classifier's
  tokens and cost (replayed cost is labelled "replayed, not billed").
- Hashes call arguments with a keyed HMAC in its own records (GATEWAY_ARGUMENT_HASH_KEY).
- Ships an acceptance test: a planted ticket tells an assistant to export every customer, a scripted
  worst-case client does it, and an independent oracle that reads the databases judges the result, with
  every layer enforcing and again with the weakenable layers in monitor mode
  (scripts/run_redteam_check.sh).

Run it
  python3 scripts/init_env.py
  docker compose up -d --build --wait
Services publish on 127.0.0.1 only: dashboard 4400, gateway 4401, PostgreSQL 4402.

Known limits (read these before relying on it)
- Egress tracks values per client over a sliding 30-minute window (any MCP session of the client), with
  every cap per client. Up to nine values can leave a client in a window before its tally of ten; other
  spellings of a phone number or id, names and notes are not matched; and a client that cites more than
  ten read values in its writes within the window is refused the next (tunable).
- Scheduled for Phase 6 (limits of this release): the classifier judges only strings of at least 24
  characters and three whitespace-separated words, so text joined with underscores or zero-width
  characters, or spread over several short values, is not judged; its units of up to 6000 characters
  have no overlap; and structured results are validated against the upstream's own schema and not
  against the pin.
- In replay mode (the default) a text with no recording is not judged: the call goes on and is recorded
  as unclassified, never as clean. A deployment must run live.
- Argument hashes in records written before the key existed are plain SHA-256. agent-core's own approval
  payload hash is not keyed.
- Any login in the approver role can decide a pending request, including the payload-purge login.
- The dashboard's sign-in redirect takes its scheme from the request URL.

Tested with: Python 3.12, PostgreSQL 17 with pgvector, Node for the dashboard. Details and the review
that found the limits above: docs/architecture.md and the pull requests for Phases 4a to 4d.
