AI Gateway v0.1.1

A patch release for v0.1.0 (the fictional Harborline Supply Co.; all data synthetic). It makes two
changes and nothing else.

What changed
- The gateway's own request id is returned in every tool result's `_meta`, under
  `io.aox.ai-gateway/request_id`: successes, a tool's own errors, writes waiting for approval and
  upstream failures alike. Every error the gateway answers a call with after authentication (a policy
  refusal, an unknown or out-of-scope tool, an internal error) carries it in `data`, as `request_id`
  (as v0.1.0 gave it on a policy refusal) and under the same `_meta` key. It is the id the audit and
  telemetry rows carry. The gateway mints it for each call; a correlation key a client sends is
  ignored and never echoed. Keys an upstream returns in its own `_meta` under `io.aox.ai-gateway/` are
  dropped, so nothing an upstream returns can pass for gateway metadata.
- The demo ticket subject "Damaged pallets on order HS-48213" is in the 09 story corpus and its
  classifier judgement is recorded, so the integrated demo runs in replay mode with no key.

Known limits
- An upstream's other result `_meta` keys are passed to the client as in v0.1.0, and no layer scans
  them (the injection classifier and egress read a result's text and structured content only). No
  AOX tool server sets one.
- A request id is on errors only once the caller is authenticated and the request is a well-formed
  tool call: the SDK's own parameter-validation errors and authentication failures carry none.
- Everything listed as a known limit in v0.1.0 still holds.
